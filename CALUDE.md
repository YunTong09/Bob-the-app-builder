# Claude Code — Project Instructions

You are working on Rage-to-Reply, an AI-powered workplace communication assistant built for an 18-hour hackathon.

Before making changes, read:

1. `AGENTS.md` — Repository-wide coding rules and responsibilities.
2. `docs/PRODUCT_SPEC.md` — Project goals, features, user flows and MVP scope.
3. `docs/ARCHITECTURE.md` — Application architecture and component ownership.
4. `docs/API_CONTRACT.md` — Shared API schemas and interfaces.

Follow these documents as the project's source of truth.

Inspect existing code before implementing changes. Preserve working functionality and avoid modifying files outside your assigned responsibility.

If documentation conflicts, identify the conflict and ask for a decision rather than silently choosing an incompatible implementation.

Prioritise a complete, working MVP over additional features.

Do not implement unrelated functionality or refactor other developers' work unnecessarily.

After each task, summarise files changed, tests performed, limitations and integration requirements.
